## 五项检验

- [ ] **1. 自述概念**

  向"懂 C 但没学过 Rust 的同事"解释这三个概念。规则：每冒出一个 Rust 术语，
  要么当场用 C 世界的话解释，要么换掉它。

  特别注意"单态化"和"vtable"—— 前者在 C 里对应"每个类型抄一份函数"，
  后者对应"函数指针表"。试着**先用 C 的话**讲完，再把 Rust 的名字对上去。

- [ ] **2. 最小示例**

  为每个 Capability **默写**一段 ≤15 行代码。默写，不是复制。

  | C-ID | 要默写的东西 |
  |------|------------|
  | C-05 | 一个能同时看出"判别式"和"变体载荷"的 enum，外加一次 `size_of` |
  | C-06 | 同一个 trait 的一个静态调用点和一个动态调用点 |
  | C-07 | 一个带 bound 的泛型函数，以及把它实例化成两种具体类型的调用 |

- [ ] **3. 底层机制**

  说出编译器实际做了什么，**并指出你的依据来自哪个实验断言或哪处源码**。

  1. `Option<&T>` 能和 `&T` 同宽时，省掉的那个字节原本该表示什么？依据是哪条断言？
  2. 指向 trait 对象的引用为什么可能比普通引用宽？宽出来的字，IR 里有没有对应物？
  3. 泛型函数的"一份源码"是在哪一步变成"多份机器码"的？你数过实例吗？
  4. 缺 bound 的拒绝发生在单态化之前还是之后？依据是哪份 compile_fail 样本？

  说不出依据的那条，标记为"待补"—— 那正是第 5 节要出题的地方。

- [ ] **4. 常见误区**

  为每个 Capability 说出至少 1 条**你自己曾经的**误解，以及推翻它的证据。

  从别处抄来的"常见误区"没有诊断价值。如果你真的一条都没误解过，
  那就去看 `predictions.md` 里 `一致? = ✗` 的那几行 —— 那就是你的误解，白纸黑字。

- [ ] **5. 验证性问题**

  回答下列问题。答案不在本文件里。

  1. 把一个 `#[repr(C)]` 结构体的两个字段对调，`size_of` 变了。
     变的是数据量，还是空位？你怎么用 `offset_of` 证明？
  2. 若语言允许 `Option<&T>` 和 `&T` 同宽，却仍把空指针当成合法的 `&T`，
     会破坏哪一条不变量？这和 C 里"空指针解引用"是同一件事吗？
  3. 同一个方法，静态分发在 IR 里是直接调用，动态分发经一张表。
     若你只比较**返回值**就断言"两种分发代价相同"，错在哪一步？
  4. 一份泛型函数对三个整数类型各调用一次。实例数是 3 还是 1？
     如果优化器把三个实例内联掉了，"单态化发生过"这件事还成立吗？你依据什么判断？
  5. trait 对象要求方法是对象安全的。如果方法返回 `Self`，为什么通常不能做成 trait 对象？
     这限制的是调用约定，还是类型信息在运行期不够？
  6. 后续读 Aya 的 `Map<K, V>` 时，你怎么判断这一次查找走的是单态化后的具体实现，
     还是一次间接调用？判断依据是签名上的哪几个记号？
