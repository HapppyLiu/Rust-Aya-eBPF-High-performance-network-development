## 五项检验

- [ ] **1. 自述概念**

  向"懂 C 但没学过 Rust 的同事"解释：**为什么**要有一个综合实验，
  而不是把 m1–m7 的通过记录订在一起就算完。

  规则：每冒出一个 Rust 术语，要么当场用 C 世界的话解释，要么换掉它。

  必须讲清的一点：单项积木都能用，不等于同一段解析代码里
  所有权、失败路径、裸指针和"没有操作系统"能同时成立。

- [ ] **2. 最小示例**

  **默写**（不是复制）下列骨架，每段 ≤15 行：

  | 分层 | 要默写的东西 |
  |------|------------|
  | 视图 | 一个带寿命参数的借用字节视图的类型头 + 一个从它切出子区间的函数签名 |
  | 解析 | 一个 trait 的方法签名 + 一处 `dyn` 参数 |
  | 错误 / 迭代 | 一个错误枚举 + `Iterator::next` 的 `Item` 类型 |
  | 原子 | 一个只含原子计数的结构体，以及你为什么**不必**手写跨线程 impl |
  | 裸指针 | 一个**安全**的读取函数：先检查长度，再（在块里）读 |
  | 布局 | 一个 `repr(C)` 头的字段顺序（不必填宽度数字） |
  | no_std | crate 顶部两行：关掉默认库、引入堆集合这一层 |

- [ ] **3. 底层机制**

  说出编译器 / 运行时实际做了什么，**并指出你的依据来自哪个实验断言或哪处源码**。

  1. 载荷视图为什么能零拷贝？依据是哪条断言（不是"看起来没 clone"）？
  2. 关联类型带上输入寿命之后，为什么那一处改成了另一个可对象化的 trait？依据？
  3. 库里没有起线程。缺的是哪一类能力？测试里起线程算不算把 C-13 做掉了？
  4. 过短切片走公开 API 时，Miri 的判定档是什么？没跑工具能不能写成"干净"？
  5. `repr(C)` 布局断言通过，能不能推出"跨语言调用也安全"？还缺哪条义务？
  6. `--no-default-features` 构建成功，能不能推出"裸机上可执行"？

  说不出依据的那条，标记为"待补"。

- [ ] **4. 常见误区**

  至少说出 5 条**你自己曾经的**误解，以及推翻它的证据。
  其中一条 MUST 针对："前面 24 项 AC 都过了，所以综合实验只是走个过场。"

  从别处抄来的"常见误区"没有诊断价值。如果你真的一条都没误解过，
  那就去看 `predictions.md` 里 `一致? = ✗` 的那几行。

- [ ] **5. 验证性问题**

  回答下列问题。答案不在本文件里。

  1. 24 项定位表里，允许写"配套说明"的是哪一类能力？说明里必须出现什么，才不算敷衍？
  2. 测试 crate 有 `std`，库没有。C-13 的体现应该写在库的原子计数上，还是写在测试的 `spawn` 上，还是两者都要写并标明边界？
  3. 去掉 `raw` 层的长度检查、只留 `unsafe` 读：综合实验的 Miri 还会是同一档吗？
  4. `Box<dyn …>` 证明了智能指针，还是证明了 trait 对象，还是两者的交界？你怎么在定位表里拆开写，避免一行充数两项？
  5. 解析借用视图时分配次数为 0，能不能推出"这个解析器永远不分配"？
  6. 本模块 Feynman 五项里，哪一项专门用来挡住"积木都会、整机不会"？
