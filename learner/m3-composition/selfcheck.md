## 五项检验

- [ ] **1. 自述概念**

  向"懂 C 但没学过 Rust 的同事"解释这四个概念。规则：每冒出一个 Rust 术语，
  要么当场用 C 世界的话解释，要么换掉它。

  特别注意：
  - `?` —— 不要只说"提前返回"，要说出失败值的类型怎么变；
  - 迭代器"惰性" —— 用 C 里"函数指针还没被调用"来对照；
  - `Fn`/`FnMut`/`FnOnce` —— 用对捕获物做了哪种动作来讲，不要背名字；
  - `Rc`/`Arc` —— 用"几只手、几个线程、clone 会不会 memcpy"来讲。

- [ ] **2. 最小示例**

  为每个 Capability **默写**一段 ≤15 行代码。默写，不是复制。

  | C-ID | 要默写的东西 |
  |------|------------|
  | C-08 | 内层 `Result` 经 `?` 变成外层 `Result`，外层错误类型实现了转换 |
  | C-09 | 一条 `map`+终端消费者的链，以及"不消费就不会跑"的对照 |
  | C-10 | 三种捕获各一个闭包（只读借 / 可变借 / 按值） |
  | C-11 | `Rc::new` + `clone`，并读一次共享计数 |

- [ ] **3. 底层机制**

  说出编译器 / 运行时实际做了什么，**并指出你的依据来自哪个实验断言或哪处源码**。

  1. `?` 失败时调用了哪个转换方法？缺了它，拒绝发生在编译期还是运行期？依据是哪条断言？
  2. `Map::next` 一次拉动取几个上游元素？求值顺序的打印和源码对得上吗？
  3. `sum` 与 `collect::<Vec<_>>` 的分配次数差在哪一步？依据是哪条 `measure` 断言？
  4. 三个调用 trait 的 `self` 形式分别是什么？捕获方式怎样对号入座？
  5. `Rc::clone` 为什么可以不分配？`Rc` 跨线程被拒，依据是源码里的哪一段？

  说不出依据的那条，标记为"待补"—— 那正是第 5 节要出题的地方。

- [ ] **4. 常见误区**

  为每个 Capability 说出至少 1 条**你自己曾经的**误解，以及推翻它的证据。

  从别处抄来的"常见误区"没有诊断价值。如果你真的一条都没误解过，
  那就去看 `predictions.md` 里 `一致? = ✗` 的那几行 —— 那就是你的误解，白纸黑字。

- [ ] **5. 验证性问题**

  回答下列问题。答案不在本文件里。

  1. 手写 `match` 和 `?` 对同一输入返回值相同。若你据此断言"两种写法的机器码也相同"，错在哪一步？
  2. 一条 `map`+`filter` 链，你在 `collect` 之前插入一行打印"链构造完毕"。
     若此时已经看到 `map` 的副作用，说明你对惰性的哪一处判断错了？
  3. `collect` 一条带精确长度提示的 `map` 链，和手写 `Vec::new`+`push` 同样多个元素，
     分配次数为什么**可以**不同？差别来自元素个数，还是来自"事先知不知道容量"？
  4. 一个闭包按引用捕获了局部变量。给它加 `move` 再 `spawn`，就能编译了吗？
     若仍不行，缺的是哪一层（生命周期还是线程安全标记）？本模块哪份样本覆盖了哪一侧？
  5. `Arc::clone` 的分配次数与 `Rc::clone` 相同，是否就能说两者代价相同？
     你**不能**用本模块的哪一类数据（耗时）去证明这一点？那该用什么确定性量？
  6. 后续在用户态持有一份要跨线程共享的句柄时，选 `Rc` 还是 `Arc`？
     判断依据是所有权合同的哪一条，而不是"习惯上用哪一个"？
