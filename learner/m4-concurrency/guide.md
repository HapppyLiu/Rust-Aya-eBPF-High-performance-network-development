## 1. 本模块你要能回答的问题

先自己答一遍，答不上来是正常的 —— 记下来，那就是你这个模块的学习目标。

### C-12 Send / Sync

1. 把一个值**移动**到另一个线程，和让两个线程**同时持有它的引用**，分别要求哪条标记？
   这两条是同一件事吗？
2. 一个类型含有内部可变性，是否就等于"不能跨线程"？如果不是，不能的是哪一种动作？
3. 容器会不会改变内部类型的标记？有的容器看起来像在**提升**能力，有的像在**原样传递**。
   你打算用哪两个标准库类型对照这件事？
4. 零大小的字段还参与推导吗？如果参与，它在推导里扮演的是"占空间"还是"带约束"？
5. `&T` 自身的两条标记，分别由 `T` 的哪一条决定？两个方向是否相同？

### C-13 Concurrency

1. `thread::scope` 和 `thread::spawn` 对闭包活多久的要求差在哪？差在寿命，还是差在标记？
2. 互斥锁保护的是"数据不会被两个线程同时碰到"，还是"两个线程完成的先后顺序"？
   哪一样可以写成稳定断言，哪一样只能当观察输出？
3. 在安全语言里写"两个线程同时改同一个普通整数"，编译器拦的是标记，还是借用规则？
   先写下你预测的**拒绝形态**，再去跑实验。
4. 绕过那条拒绝需要承担什么义务？本模块会不会用 `unsafe` 去绕？

### C-14 Atomic

1. 原子类型和 `Cell` 都有内部可变性。为什么一个可以共享，一个不行？差别在"有没有内部可变性"，还是在修改方式？
2. 内存序从最强放到最弱之后，**哪些执行顺序**从"不可能"变成"可能"？
   先写进预测表，再跑 example。
3. 在本机（x86_64）上放宽内存序之后，若你仍然看到"像最强序那样"的结果，
   这能证明弱序在别的架构上也安全吗？
4. 哪些量可以断言（总和、握手后读到的载荷），哪些量不能断言（线程谁先结束、某次弱序一定看见旧值）？

## 4. 提示阶梯

逐级往下看，每次只看一级。

### C-12 Send / Sync

- **Hint 1（方向）**：先别背"哪个类型能进线程"。拆成两问：
  所有权换到另一个线程，安全吗？两个线程同时拿着引用，安全吗？
- **Hint 2（位置）**：`core/src/marker.rs` 里两个 auto trait 的方法体是空的。
  真正的判断在字段推导和显式 impl。去 `cell.rs` 看内部可变性那一对正/负 impl。
- **Hint 3（拆解）**：(a) 只**移动**一个带内部可变性的值；(b) **共享**它的引用。
  两个样本不要写成同一个。正向用 `assert_send` / `assert_sync`，负向用 compile_fail。

### C-13 Concurrency

- **Hint 1（方向）**：互斥锁保证的是"同一时刻最多一只手在改"，不是"谁先跑完"。
  打印出来的完成顺序如果每次不一样，先问自己：哪一个量仍然必须相同。
- **Hint 2（位置）**：`std/src/thread/` 里找两个创建入口的 bound。
  再在 `std/src/sync/` 里找互斥锁对内部类型的条件 —— 和 C-12 的"提升 / 原样传递"对上。
- **Hint 3（拆解）**：数据竞争样本写成"两个线程各拿一份对同一局部变量的可变借用"。
  先预测拒绝形态，再编译。不要先加锁把竞争消掉再声称"看，安全语言没有数据竞争"。

### C-14 Atomic

- **Hint 1（方向）**：原子操作先保证"这一次读写不会撕成两半"。
  内存序是另一问：周围那些**别的**读写，能不能被看到、以什么顺序被看到。
- **Hint 2（位置）**：打开 `atomic.rs` 里的内存序枚举，读最弱和"先写后读"那两个变体的注释。
  再跑 `c14_atomic` 的握手对照：一侧用释放/获取，一侧两边都放宽。
- **Hint 3（拆解）**：本机是 x86_64。若放宽之后打印仍然"看起来正确"，
  先写"这不能证明什么"，再去 OBSERVATIONS 核对架构相关性那一行（先别翻答案正文）。
