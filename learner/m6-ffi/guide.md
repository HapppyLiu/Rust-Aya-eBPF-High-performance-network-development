## 0. 开始之前

- **前置模块**：m5（C-15…C-20），当前验收状态：查 `acceptance/capability-matrix.md`。
- **本模块假定你已经能**：
  - 给一个 `unsafe` 块写出有效性 / 对齐 / 别名 / 来源 / 生命周期五要素（C-15）；
  - 说明裸指针不延长分配寿命，释放后再读为什么犯规（C-16）；
  - 把"本机没崩"和"语言合法"拆开（C-18 / C-20）。
- **本模块结束时你应该能**：独立完成一次 Rust 调 C 与 C 调 Rust；
  两侧结构体的大小、对齐、字段偏移能对上，并且你能说出对上是靠什么约束，而不是碰巧；
  指出跨边界分配由哪一侧释放，以及约定拆掉时会以哪种故障出现；
  把一次失败的 Linux 调用封装成 Rust 错误类型，且原始错误码还在。

**为什么排在 m5 之后**：跨语言边界上的每一步几乎都是裸指针。
不会写 Safety 不变量，这边的 `extern "C"` 只是把炸弹换了个包装。

**本模块的工作方式**：C 源码由构建脚本编进来，和 Rust 链在一起。
布局、双向调用、所有权、错误码是四组实验，但同属一项能力。
**先填预测表，再跑。** 先跑再填等于没预测。
本模块的未定义行为判定工具不是上一模块那套解释器 —— 命令在预测表里。

## 1. 本模块你要能回答的问题

先自己答一遍。答不上来是正常的 —— 记下来，那就是你这个模块的学习目标。

### C-21 FFI

1. Rust 结构体的默认布局能不能当成和 C 同一个结构体？若不能，缺的是哪一类承诺？
2. 什么样的约束才能让两侧的大小、对齐、字段偏移变成可核对的契约，而不是某次编译的巧合？
   只在一侧写了某种表示属性，但从来没有量过另一侧，这算不算已经证明一致？
3. 一次跨边界的分配，所有权交到对面之后，谁负责释放？约定两边各释放一次、或谁都不释放，
   分别会以什么形态出问题？这些问题在普通退出码为 0 的运行里一定看得见吗？
4. 内核把失败写成一个整数错误码。封装成 Rust 惯用的错误类型之后，
   原来的那个整数还在不在？封装这一层悄悄加进了哪些假设（例如"什么时候去读这个码"）？
5. `c_int` / `c_char` 和 Rust 的 `i32` / `char` 是不是同一件事？C 字符串的长度记在哪？

## 4. 提示阶梯

逐级往下看，每次只看一级。**每一级都不给答案。**

### C-21 布局

- **Hint 1（方向）**：问的不是"字段名字一样吗"，而是"编译器有没有承诺按同一套规则排字段"。
  没有承诺的那一侧，字段顺序和对齐填充都可以变。
- **Hint 2（位置）**：Rust 侧用 `size_of` / `align_of` / 字段偏移宏量一遍。
  C 侧不要口算，让 C 函数把 `sizeof` / `_Alignof` / `offsetof` 的结果返回来。
  两列对在一起，才叫一致。
- **Hint 3（拆解）**：只在 Rust 侧加了一种表示属性、从来没问过 C 编译器，缺了哪一列？
  把"声明了某种表示"和"两侧量过且相等"写成两句，看它们是不是同一件事。

### C-21 双向调用

- **Hint 1（方向）**：两个方向是两条契约，不要合成一句"FFI 能跑"。
- **Hint 2（位置）**：Rust 调 C：`extern` 声明 + `unsafe` 调用。
  C 调 Rust：Rust 侧导出一个约定好的符号，C 侧声明再调用，Rust 再调这个 C 包装把结果带回来。
- **Hint 3（拆解）**：每个方向单独写一条断言。传结构体时，用指针，避免先踩"按值传递的 ABI 细节"。

### C-21 所有权

- **Hint 1（方向）**：分配器和释放器必须成对。跨语言之后，"谁 `malloc` 的谁 `free`"仍然成立，
  只是两半写在不同的源文件里。
- **Hint 2（位置）**：先在注释里写清约定（哪一侧分配、哪一侧释放）。
  再写一次释放。不要在稳定断言里真的释放两次。
- **Hint 3（拆解）**：约定拆掉的两种形态（两边都释放 / 谁都不释放）分别会变成哪类故障？
  写进观察记录。普通退出码 0 看不见的那种，用本模块的判定脚本想一想它能不能看见。

### C-21 错误码

- **Hint 1（方向）**：内核给你的是一个整数。Rust 的 `Result` 是包装。包装可以加字，但不许把整数弄丢。
- **Hint 2（位置）**：失败之后立刻读出原始码，再封装。中间不要插入别的 libc 调用。
- **Hint 3（拆解）**：断言 `raw` 那一层还在。诊断字符串会随语言环境和 libc 版本变，不要拿全文当稳定断言。
  然后列出封装层引入的假设：线程局部、读取时机、路径必须是 C 字符串。

### 怎么自己写 Safety 五要素（本模块共用）

- **Hint 1（方向）**：跨边界不等于五要素作废。指针从 C 回来，有效性、寿命、来源仍然要你说。
- **Hint 2（位置）**：对着刚写的那一个 `unsafe` 块逐项问：这块是谁分配的、对齐谁保证、
  对面会不会同时写、指针还记不记得那次 `malloc`、释放之后还能不能再用。
- **Hint 3（拆解）**：哪一项与这个块无关，写"不适用，因为…"。
  写完用 `cargo clippy -p m6-ffi --all-targets -- -D warnings` 做机械兜底。
