# Learner Track — Module 3: 组合能力

**Story**: US3（P2） | **Capabilities**: C-08…C-11 | **Prerequisite**: m2（已 accepted）

> 本文件属于 **Learner Track**，不含答案。

## 0. 开始之前

- **前置模块**：m2（C-05…C-07），当前验收状态：查 `acceptance/capability-matrix.md`。
- **本模块假定你已经能**：
  - 读懂 `enum` 变体和 `Result` 这种"带标签的结果"（C-05）；
  - 区分静态分发与动态分发，并知道 trait bound 写在哪一侧（C-06 / C-07）；
  - 说出一个值的所有者、一次移动发生在哪一行（C-01 / C-02）。
- **本模块结束时你应该能**：把一段显式错误码 + 手写循环改写成惯用的 `Result` 与迭代器版本，
  两版行为一致；对一条多阶段迭代器链，在**不运行**的前提下预测求值顺序与**分配次数**，
  并能说明三种闭包捕获、三种智能指针各自约束的是哪一种所有权。

**为什么排在 m2 之后**：`?`、迭代器适配器、闭包、`Rc`/`Arc` 全是 trait 与泛型的日常用法。
分不清"这次调用走哪份 `impl`"，后面就说不清 `?` 为何要 `From`、闭包为何是 `Fn` 而不是 `FnOnce`。
闭包捕获与智能指针的所有权，又是 US4 Send/Sync 的直接前置。

## 1. 本模块你要能回答的问题

先自己答一遍，答不上来是正常的 —— 记下来，那就是你这个模块的学习目标。

### C-08 Error handling

1. `Result` 比"返回一个整数错误码"多了哪一条语言级约束？少了哪一种 C 里常见的失误？
2. `?` 在成功和失败两条路径上分别做了什么？失败那条为什么常常还要再走一次类型转换？
3. 那个转换 trait 要求谁实现谁？缺了它时，编译器拒绝的是"运行结果不对"，还是别的？
4. 把错误码写法改成 `Result` + `?` 之后，**可观察的行为**应该变还是不变？变的是哪一层？
5. 标准库的"错误"接口除了能打印，还要求你能做什么（比如指向更底层的原因）？

### C-09 Iterator

1. 迭代器适配器（`map` / `filter` 这类）在被写出的那一行就开始跑了吗？如果没有，谁扣动扳机？
2. 一条多阶段链的求值顺序是"先把第一段全部做完再做第二段"，还是"一个元素走完整条链再取下一个"？
3. 手写 `for` + `push` 和 `collect` 到同一个容器，**元素结果**能一致吗？**分配次数**也一定一致吗？
4. `sum` 一条只含整数的链，和 `collect` 成 `Vec` 的同一条链，堆分配各发生在哪一步？
5. 适配器结构体里到底存了什么？为什么"必须被消费"会出现在它的文档里？

### C-10 Closure

1. 闭包捕获环境里的变量，一共有几种方式？每种分别拿走的是什么（只读借、可变借、所有权）？
2. `Fn` / `FnMut` / `FnOnce` 三个 trait 是平级的三种接口，还是一条继承链？调用时对 `self` 的要求差在哪？
3. 捕获方式如何决定闭包属于上面哪一层？把一个按值拿走 `String` 的闭包当成"可重复调用"会怎样？
4. 捕获方式如何决定这个闭包能不能被送到另一个线程？先写下你预测的**拒绝形态**，再去跑实验。
5. 这一问是给 US4 预埋的：闭包跨线程，真正被检查的是捕获物的哪条性质，而不只是"它是一个闭包"？

### C-11 Smart pointer

1. `Box` / `Rc` / `Arc` 三种指针，各自允许的所有权形态是什么（独占 / 单线程共享 / 跨线程共享）？
2. `clone` 一个 `Rc` 或 `Arc`，堆上的值被复制了吗？你打算用什么**可观察量**证明？
3. 为什么 `Rc` 不能进 `thread::spawn`？这条拒绝来自所有权，还是来自线程安全标记？
4. 选错指针的**具体后果**是什么——编译失败、运行期共享出错、还是多付一笔你说不清的代价？
5. 选择依据应当是所有权语义。若只凭"大家都用 Arc"来选，后面读用户态共享句柄时会漏掉哪一类错误？

### compile_fail 样本的写法

编译失败的样本放在 `experiments/m3-composition/compile_fail/`，首行声明你**事先**预测的错误码：

```rust
//! EXPECT: <你预测的错误码>
//! CLAIM: <这个样本违反了哪条规则>
```

然后在 `tests/` 里用 `rf_harness::compile_fail::expect_errors` 断言。
**先写** `EXPECT` **再编译** —— 反过来就只是抄写编译器输出。

### 分配计数（C-09 / C-11）

本模块用 `rf_harness::counting_alloc::measure` 数**请求次数**，不数耗时。
计数器按线程隔离，所以并行测试不会把别人的分配算进你的区间。
但分配器一旦注册，对**整个测试二进制**生效 —— 这一条要写进你自己的笔记，
具体说明见 Answer Track 的 `OBSERVATIONS.md`（先别翻）。

## 4. 提示阶梯

逐级往下看，每次只看一级。

### C-08 Error handling

- **Hint 1（方向）**：不要先背 "`?` 等于提前 return"。拆成两问：
  成功时留下什么、失败时返回值的**类型**为什么可以和内层函数的错误类型不同。
- **Hint 2（位置）**：在 `core/src/result.rs` 里搜失败值被包进另一种 `Err` 的那段。
  再看 `core/src/convert/` 里那个转换方法。两处对上，缺的 impl 就有着落了。
- **Hint 3（拆解）**：(a) 行为——同一组输入，手写 `match` 和 `?` 的 `Ok`/`Err` 是否一致；
  (b) 类型——缺转换时失败发生在编译期还是运行期。两问不要混。

### C-09 Iterator

- **Hint 1（方向）**：把"写出链"和"拉动链"拆开。适配器那一行如果已经跑完了，
  你在终端消费之前就该看到副作用。去 example 里看副作用实际出现在哪。
- **Hint 2（位置）**：打开 `map.rs` 的 `next`。数一数：一次 `next` 调用了几次上游 `next`、
  几次闭包。再跑 `c09_iterator` 的打印，把两者对上。
- **Hint 3（拆解）**：元素结果一致，不代表分配次数一致。
  分别 `measure` 三条闭包：只 `sum`、`map` 后 `collect`、手写 `push`。
  问自己：谁在构造容器之前就已经知道长度。

### C-10 Closure

- **Hint 1（方向）**：先别记三个 trait 的名字。问闭包对捕获物做了哪一种所有权动作：
  只看、改、还是拿走。动作决定它能被调用几次、以什么 `self`。
- **Hint 2（位置）**：`core/src/ops/function.rs` 里三个 trait 的 `self` 形式就写在方法签名上。
  谁是谁的超 trait，看 `: ` 后面。
- **Hint 3（拆解）**：跨线程是另一问。把"捕获了借用"和"捕获了所有权但不满足线程安全标记"
  分成两个样本想 —— 本模块的 compile_fail 只覆盖其中一侧，另一侧在 C-11。

### C-11 Smart pointer

- **Hint 1（方向）**：三种指针不是"好 / 更好 / 最好"，是三种**所有权合同**。
  先写出合同（几个所有者、几个线程），再看误用时编译器拦的是合同的哪一条。
- **Hint 2（位置）**：`rc.rs` 结构体定义附近有两条负向 impl；`sync.rs` 里对应的是带 bound 的正向 impl。
  `clone` 函数体里搜计数相关的调用，看有没有新的堆分配。
- **Hint 3（拆解）**：用 `measure` 分别包住"新建"和"再 clone 一次"。
  用 `strong_count` 看共享边。分配次数回答"有没有新盒子"；计数回答"有几只手抓着同一个盒子"。
