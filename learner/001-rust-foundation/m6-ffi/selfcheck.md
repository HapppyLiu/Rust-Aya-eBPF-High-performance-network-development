## 五项检验

- [ ] **1. 自述概念**

  向"懂 C 但没学过 Rust 的同事"解释 FFI 这一项。规则：每冒出一个 Rust 术语，
  要么当场用 C 世界的话解释，要么换掉它。

  特别注意：
  - 默认布局 —— 讲清"没有承诺"和"这次碰巧排得一样"不是一回事；
  - 表示属性 —— 讲清它是契约的一半，另一半是对面那份量出来的数字；
  - 跨边界释放 —— 讲清约定写在哪，拆掉时是泄漏还是重复释放；
  - 错误封装 —— 讲清包装以后原来的那个整数还在不在。

- [ ] **2. 最小示例**

  为 C-21 **默写**一段 ≤15 行代码。默写，不是复制。

  | C-ID | 要默写的东西 |
  |------|------------|
  | C-21 | 一个带表示约束的结构体 + 一次 `extern` 调用（或一次导出给 C 的函数） |

- [ ] **3. 底层机制**

  说出编译器 / 运行时 / C ABI 实际做了什么，**并指出你的依据来自哪个实验断言或哪处源码**。

  1. 为什么默认布局不能拿去跟 C 结构体对字段？依据在哪？
  2. 两侧 `size_of` / 字段偏移一致，证明的是"我写了某种属性"，还是"两边的编译器按同一套 ABI 排出了相同的图"？哪条断言在核对后一件事？
  3. C 分配、Rust 释放：哪一次 `unsafe` 对应 `malloc` 的配对物？依据是哪条断言或哪段 C 源码？
  4. `open` 失败后，若先调用别的 libc 函数再去读错误码，会怎样？封装层把哪条假设写进去了？
  5. 判定脚本退出码 0，能不能写成"这段 FFI 没有未定义行为"？缺了哪一句强度声明？

  说不出依据的那条，标记为"待补"。

- [ ] **4. 常见误区**

  为 C-21 说出至少 1 条**你自己曾经的**误解，以及推翻它的证据。

  从别处抄来的"常见误区"没有诊断价值。如果你真的一条都没误解过，
  那就去看 `predictions.md` 里 `一致? = ✗` 的那几行 —— 那就是你的误解。

- [ ] **5. 验证性问题**

  回答下列问题。答案不在本文件里。

  1. 只在 Rust 侧加了表示约束、从未调用 C 侧的 `sizeof` 导出函数，布局实验还算不算通过？缺的是哪一列？
  2. Rust→C 过了、C→Rust 没写断言。SC 里的"双向"过了吗？
  3. 约定是 C 分配、Rust 释放。你若在 Rust 里再调一次 C 的释放，判定脚本预期会看见什么形态？本模块为什么不把这件事做成稳定断言？
  4. 封装后的错误 `Display` 在中文环境和英文环境字面不同。你该断言哪一层，才算"原始信息未丢失"？
  5. `c_char` 在本机是有符号还是无符号？这件事是语言保证对所有目标成立，还是跟了当前 C ABI？你去哪份源码核对？
  6. 用户态后面要跟内核结构体、syscall 缓冲区打交道。本模块哪一条实验对应"先量两侧再相信布局"，而不是"我以为字段顺序就是声明顺序"？
