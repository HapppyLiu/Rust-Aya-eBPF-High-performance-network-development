## 五项检验

- [ ] **1. 自述概念**

  向"懂 C 但没学过 Rust 的同事"解释这三个概念。规则：每冒出一个 Rust 术语，
  要么当场用 C 世界的话解释，要么换掉它。

  特别注意：
  - 两条线程安全标记 —— 用"换主人"和"同时看"来讲，不要混成一句"能不能进线程"；
  - 互斥锁 —— 讲清它保证的是互斥，不是完成顺序；
  - 内存序 —— 用"这一次读写会不会撕裂"和"周围别的读写能不能被看见"拆开。

- [ ] **2. 最小示例**

  为每个 Capability **默写**一段 ≤15 行代码。默写，不是复制。

  | C-ID | 要默写的东西 |
  |------|------------|
  | C-12 | 一个能**移动**但不能**共享**的内部可变性类型，以及一个把它包进互斥锁之后的对照 |
  | C-13 | `scope` 里两线程经互斥锁累加，只关心总和 |
  | C-14 | 一次释放/获取握手：先写载荷再立旗标，另一侧看见旗标再读载荷 |

- [ ] **3. 底层机制**

  说出编译器 / 运行时实际做了什么，**并指出你的依据来自哪个实验断言或哪处源码**。

  1. 那两个 auto trait 的方法体是空的。真正的判断发生在哪（推导 / 显式 impl）？
  2. 互斥锁对内部类型的 `Sync` 条件写的是哪一条？依据是源码里的哪一段？
  3. 安全语言里两个线程同时 `+=` 同一局部变量，拒绝发生在标记还是借用？依据是哪条断言？
  4. 原子类型为什么可以 `Sync`，而同样含内部可变性的 `Cell` 不行？
  5. 释放/获取握手保证的是哪一件事？`SeqCst` 累加保证的又是哪一件事？

  说不出依据的那条，标记为"待补"—— 那正是第 5 节要出题的地方。

- [ ] **4. 常见误区**

  为每个 Capability 说出至少 1 条**你自己曾经的**误解，以及推翻它的证据。

  从别处抄来的"常见误区"没有诊断价值。如果你真的一条都没误解过，
  那就去看 `predictions.md` 里 `一致? = ✗` 的那几行 —— 那就是你的误解，白纸黑字。

- [ ] **5. 验证性问题**

  回答下列问题。答案不在本文件里。

  1. `Cell<u32>` 可以移动到另一个线程。若你据此说"含内部可变性的类型都能跨线程共享"，错在哪一步？
  2. `Mutex<Cell<u32>>` 可以共享。这是不是意味着 `Cell` 自己变成了可共享？
     提升发生在哪一层？
  3. 你跑了一次 example，四个线程按 0、1、2、3 的顺序打印结束。
     若据此断言"互斥锁保证了这个完成顺序"，错在哪？本模块哪条断言才是不变量？
  4. 两边都用最弱内存序的握手，在本机打印里仍然看到了正确载荷。
     这能证明这段程序在弱序架构上仍然正确吗？你不能用哪一类数据（某一次打印）去证明？
  5. 题集里有一道守卫类型：一条标记成立、另一条不成立。
     若你一直以为"能共享就一定能移动"，这道题会怎样打你的脸？
     （不要在本文件写下那一题的判定，去题集里自己推。）
  6. 后续读用户态里对共享映射的并发访问时，你先问"要移动还是要共享"，
     还是先问"大家是不是都加了锁"？缺了哪一问会把 C-12 和 C-13 混成一句？
