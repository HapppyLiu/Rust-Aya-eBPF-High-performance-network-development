# Learner Track — Module 5: Unsafe Rust 与裸指针内存模型

**Story**: US5（P1，Feature 002 硬前置） | **Capabilities**: C-15…C-20 | **Prerequisite**: m4（已 accepted）

> 本文件属于 **Learner Track**，不含答案。
> Answer Track 在 `learning/m5-unsafe/`、`feynman/m5-unsafe.md` 与 `experiments/m5-unsafe/`。
> 什么时候可以翻，见 §5。

## 0. 开始之前

- **前置模块**：m4（C-12…C-14），当前验收状态：查 `acceptance/capability-matrix.md`。
- **本模块假定你已经能**：
  - 指出一个值的所有者，以及一次借用发生在哪一行（C-01 / C-03）；
  - 把"换主人"和"同时看"拆成两条标记，而不是混成一句"能不能进线程"（C-12）；
  - 说出互斥保证的是同时最多一只手，不是完成顺序（C-13）。
- **本模块结束时你应该能**：读一段含 `unsafe` 的代码，自己写出完整的 Safety 不变量；
  指出裸指针运算、对齐、别名、来源（provenance）里哪一处一破就是未定义行为；
  判断一个"对外安全"的封装是真安全，还是只要按某种顺序调用就会穿帮。

**为什么排在 m4 之后**：`unsafe` 要你亲手保证的，正是前面几模块由编译器代劳的那些事——
所有权、借用、以及"两只手会不会同时改同一格"。分不清共享模型，后面的别名实验会对不上。

**本模块的工作方式**：每项能力都是一对实验。一侧是正确用法（预期：工具判干净），
一侧是故意违反（预期：工具报告某一类问题）。**先填预测表，再跑。** 先跑再填等于没预测。

## 1. 本模块你要能回答的问题

先自己答一遍。答不上来是正常的 —— 记下来，那就是你这个模块的学习目标。

### C-15 Unsafe Rust

1. `unsafe` 关键字打开的是什么？是"这段代码没有规则"，还是"规则改由你来保证"？
2. 一个函数标了 `unsafe`，调用它时你必须在注释里写清什么？写"语言要求这里用 unsafe"算不算写清了？
3. 普通运行没有崩溃，能不能当成"没有未定义行为"？若不能，缺的是哪一类证据？
4. 在已经用安全 API 确认过下标合法之后，再走不检查边界的那条路径，注释里要交代的是哪一件事？

### C-16 Raw pointer

1. 从引用拿到裸指针，和从引用再借一次，差别在哪？哪一步开始编译器不再帮你盯着别名？
2. `read` / `write` 各自要求指针满足什么？只要求"非空"够不够？
3. 一块内存被释放之后，原先的指针还在。读它，普通运行可能看见什么？那能证明什么？

### C-17 Pointer arithmetic

1. 在同一块分配里挪动指针，和挪出这块分配，规则差在哪一步？是"解引用才算"，还是"算出越界指针本身"？
2. 有一种加法即使算出分配外的地址也不立刻犯规。它和另一种加法的分工是什么？
   算出那个外指针之后，你还能不能解引用？
3. 两个指针的**差值**（以元素大小为单位）可以断言吗？具体地址数值可以断言吗？

### C-18 Alignment

1. 一种类型要求的对齐，和一块具体内存是否满足该对齐，分别用什么量出来？
2. 本机（x86_64）上，未对齐的多字节读写常常能跑完并打印一个"看起来合理"的数。
   这能证明该读写在语言里合法吗？能证明在别的架构上也安全吗？
3. 有一种读专门声明"我不要求对齐"。它和普通读的分界在哪？换一种读，同一地址会怎样？

### C-19 Aliasing

1. 内部可变性的根类型做了什么，才让"通过共享引用改里面"在规则上说得通？
2. 两份可变借用叠在同一块内存上，编译器在安全语言里会怎样？用裸指针绕过去之后，
   缺的那道检查改由谁来做？
3. 两套别名模型对同一段代码可能给出不同结论。若一只报问题、另一只不报，你该取严还是取宽？
   这件事该不该被抹平写成"两套必须一致"的断言？

### C-20 Memory safety

1. 从一个裸指针 + 长度拼出切片，调用方必须保证哪几件事？漏掉边界检查会怎样？
2. 把向量的"已初始化长度"改成容量，但里面其实没写过。随后按普通切片去读，谁在撒谎——
   调用方，还是这个封装？
3. 一段带边界检查的字节解析，把检查拿掉之后，本机不一定崩。那和后续在加载时做静态边界证明
   的那套系统，证明义务分别放在哪个阶段？本实验**不要**去写那种程序，只把对应关系写清楚。

## 4. 提示阶梯

逐级往下看，每次只看一级。**每一级都不给答案。**

### C-15 Unsafe Rust

- **Hint 1（方向）**：先把"关键字打开了什么"和"崩溃了没有"拆开。工具没跑的时候，你缺的是判定，不是安心。
- **Hint 2（位置）**：去 `core/src/slice/` 读那两个不检查下标的方法的 Safety 段。
  注意它有没有写"结果不用就不算"。再跑一对实验。
- **Hint 3（拆解）**：给安全侧那个块列一张五列表，每格只写"成立，因为…"或"不适用，因为…"。
  写完再和自己的预测表对照，不要先去翻别人的注释。

### C-16 Raw pointer

- **Hint 1（方向）**：裸指针不延长借用。所有权走了以后，指针值可能还在。
- **Hint 2（位置）**：`core/src/ptr/` 里 `read` / `write` 的 Safety。对照 `Box::into_raw` 再拼回去、再丢掉。
- **Hint 3（拆解）**：安全侧只断言"两个取址是否指向同一位置"和"写进去的值能否读回来"。
  具体数字地址留给观察输出。

### C-17 Pointer arithmetic

- **Hint 1（方向）**：问清楚"犯规发生在算出指针时，还是用它去碰内存时"。
- **Hint 2（位置）**：`const_ptr.rs` 里三种挪动。看哪一个的 Safety 写的是"本操作永远安全"。
- **Hint 3（拆解）**：同一起点，分配内走一步：两种加法得到的指针相不相等？
  再单独构造"那种会立刻犯规的加法"，不要和解引用混在同一个块里。

### C-18 Alignment

- **Hint 1（方向）**：硬件宽容 ≠ 语言合法。本机打印出一个数，只说明这一次没以崩溃的形式表现出来。
- **Hint 2（位置）**：先量类型要求的对齐，再量指针地址对它取模。
  普通读和对齐豁免的读，对同一未对齐地址，工具怎么说？
- **Hint 3（拆解）**：对照侧**先** `cargo run --example …`，**再**交给工具。
  两步的输出一起记。不要只用其中一步下结论。

### C-19 Aliasing

- **Hint 1（方向）**：共享引用默认不许改。根类型把"改"重新变成一件你必须自己协调的事。
- **Hint 2（位置）**：`cell.rs` 里这个根类型怎么交出指针、自己带哪条负向标记。
  对照侧用裸指针叠两份可变，分别跑默认模型和带另一套别名模型开关的那一轮。
- **Hint 3（拆解）**：两轮各写一条断言，绑定各自的模型。
  若结论不一致，去计划文档里那张四格表看该取哪一侧，并在观察记录里单开一块写差异来源。
  不要写"两轮必须相同"。

### C-20 Memory safety

- **Hint 1（方向）**：安全封装的意思是：调用方即使用尽公开 API，也拼不出未定义行为。
  若存在一条合法调用序列会穿帮，那是封装在撒谎，不是调用方不会用。
- **Hint 2（位置）**：`from_raw_parts` 和只改长度的那个向量方法。
  再做"带检查的字节解析 → 拿掉检查"对照（`c20_bounds_check`）。
- **Hint 3（拆解）**：五列表照旧自己写。关联小节要回答三问：本机为什么不一定崩；
  运行时检查、编译期类型、加载时静态证明，义务各在哪一阶段；同一段解析在后续环境里会被要求补上什么，
  对应本实验哪一行。不要去写那种程序。

### 怎么自己写 Safety 五要素（所有能力共用）

- **Hint 1（方向）**：把五件事当成清单，而不是一段散文。缺一项就等于没写完。
- **Hint 2（位置）**：对着你刚写的那一个 `unsafe` 块，逐项问：
  这块内存还在吗、对齐够不够、还有没有别人的冲突引用、指针还记不记得它来自哪次分配、
  指向的东西是不是还活着。
- **Hint 3（拆解）**：哪一项与这个块无关，写"不适用，因为…"。
  对照侧被你故意打破的那一项，写"故意不成立，因为本实验要观察什么"。
  写完用 `cargo clippy -p m5-unsafe --all-targets -- -D warnings` 做机械兜底，
  再自己读一遍是不是在说空话。
