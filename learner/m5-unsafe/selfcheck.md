## 五项检验

- [ ] **1. 自述概念**

  向"懂 C 但没学过 Rust 的同事"解释这六个概念。规则：每冒出一个 Rust 术语，
  要么当场用 C 世界的话解释，要么换掉它。

  特别注意：
  - `unsafe` —— 讲清它打开的是义务，不是豁免；
  - 未定义行为 —— 不要讲成"会崩溃"；
  - 对齐 —— 本机没崩和语言合法是两件事；
  - 安全封装 —— 讲清"调用方无法拼出问题"和"作者自己用了不安全操作"可以同时成立。

- [ ] **2. 最小示例**

  为每个 Capability **默写**一段 ≤15 行代码。默写，不是复制。

  | C-ID | 要默写的东西 |
  |------|------------|
  | C-15 | 先确认下标合法，再走不检查边界的那条路径 |
  | C-16 | 取址、写入、读回；不要把具体地址写进断言 |
  | C-17 | 分配内走一步，读到预期元素 |
  | C-18 | 量对齐，并用对应对齐的方式去读 |
  | C-19 | 通过内部可变性的根类型改一次值 |
  | C-20 | 对外安全的"从字节缓冲读两个字节"，越界时返回空而不是硬闯 |

- [ ] **3. 底层机制**

  说出编译器 / 运行时 / 工具实际做了什么，**并指出你的依据来自哪个实验断言或哪处源码**。

  1. 不检查下标的方法，即使结果立刻丢掉，为什么仍然可能已经犯规？依据在哪？
  2. 释放后再读，普通运行看见一个数，这能当成"没有问题"吗？哪一条判定才算数？
  3. 越出分配的加法和环绕加法，犯规发生在哪一步？依据是源码哪一段？
  4. 未对齐的多字节读在本机打印出了数。这不能证明什么？
  5. 两套别名模型结论不一致时，你按哪条规则取值？依据是计划文档里的哪一格，还是自己觉得？
  6. 一个封装若存在"调用方没做错、仍然穿帮"的序列，问题出在哪一层？

  说不出依据的那条，标记为"待补"。

- [ ] **4. 常见误区**

  为每个 Capability 说出至少 1 条**你自己曾经的**误解，以及推翻它的证据。

  从别处抄来的"常见误区"没有诊断价值。如果你真的一条都没误解过，
  那就去看 `predictions.md` 里 `一致? = ✗` 的那几行 —— 那就是你的误解。

- [ ] **5. 验证性问题**

  回答下列问题。答案不在本文件里。

  1. 你去掉字节解析里的边界检查之后，工具会报告哪一类问题？先写 W 编号，再去跑对照实验核对。
  2. 普通运行打印了一个"合理"的数，你据此写"所以没有未定义行为"。缺了哪一步？
  3. Safety 注释里有一项你写了"不适用"。若其实适用，漏掉它会让哪一类问题从眼皮底下滑走？
  4. 两套别名模型一个报、一个不报。你若把"两轮结果相同"写成稳定断言，错在哪？
  5. 一个函数对外是安全的，对内用了 `unsafe`。怎样判断它是真封装，而不是把炸弹藏在接口后面？
  6. 同一段解析，运行时检查、类型系统、加载时静态证明，各把义务放在哪个阶段？
     本模块哪一行对照对应"拿掉检查"？不要去写那种后续环境里的程序。
