## 1. 本模块你要能回答的问题

先自己答一遍，答不上来是正常的 —— 记下来，那就是你这个模块的学习目标。

### C-01 Ownership（所有权）

1. "所有权"约束的到底是什么？它和 C 里"谁负责 `free`"是同一件事吗？如果是，差别在哪？

所有权约束的是一个值的生命周期，如果持有该值的变量退出作用域，则自动释放所有权和该值所占的资源。  
与C中的谁负责free是同一件事，只是在C中由程序员自己负责free，而在rust 中由编译器和运行时负责。

2. 一个值在什么时刻被销毁？这个时刻是由**谁**决定的 —— 程序员、运行时、还是编译器？

当拥有该值的变量退出作用域时被销毁。是由编译器决定的。  

3. 如果把一个值传进函数，它的销毁时刻会变吗？往哪个方向变？

如果传递的是该值的所有权，那么它的销毁时刻就由当前函数决定；  
如果传递的是该值的引用，那么销毁的时刻由原函数决定。  

4. Rust 没有 GC，也不要求你手写释放。那"释放"这段代码到底存在于哪里？

释放代码是由编译器自动加入的 drop方法。  

5. 同一个作用域里声明了三个值，它们的销毁顺序是什么？为什么是这个顺序而不是反过来？

销毁顺序是从后往前销毁，不能反过来是因为前面的值有可能被后面的值引用，无法确定它是否可以释放。  

### C-02 Move semantics（移动语义）

1. `let b = a;` 这一行，对不同类型可能有两种完全不同的含义。是哪两种？分界线在哪？

~~对于实现了Clone trait 的类型，它会复制一份a的值，b拥有复制后值的所有权；~~  
~~对于没有实现Clone trait 的类型，会将 a 的所有权转移给 b。~~  
~~分界线在于有没有实现 Clone trait。~~  
两种不同的含义分别是Move 和 Copy。
Move是将a的栈内存按位复制给b，然后将a标记为不可以用；
Copy同样是将a的栈内存按位复制给b，之后a还可以再使用。
分界线是类型是否实现了Copy trait。

2. 「移动」在机器层面到底发生了什么？是不是"把数据搬到另一个地方"？

  ~~移动在机器层面是将一块内存的所有权转移给另一个变量，即有一个新的变量指向这块资源，旧的变量不在有效。~~  
  ~~移动不是把数据搬到另一个地方。~~  
  移动在机器层面将数据复制一份给新的变量；即将变量指向的栈内存复制一份，如果变量包含堆内存，则堆内存的数据完全不会动。

3. 为什么有些类型可以在赋值后继续用原变量，有些不行？谁决定的？

~~可以继续使用的类型实现了 Clone trait。由是否实现了 Clone trait。~~  
是由类型是否实现了 Copy trait 决定的。实现了 Copy trait 的变量赋值后可以继续使用，没有实现该trait的则无法使用。
是否可以实现Copy trait 取决于该类型的数据是存储于栈上还是堆上。栈上存储复制成本较小，因此可以实现Copy trait;堆上数据则无法实现该trait.

4. 有没有办法"把值从一个位置取走，但那个位置还得留着能用"？这需要什么前提条件？

~~有，该类型需要实现clone trait~~  
有，前提条件是该值可以被新值填充、该值具有默认值、或者本身可以为空。

5. 有没有办法让一个值**永远不被销毁**？如果有，那它占的资源去哪了？这算内存泄漏还是 UB？

有，使用Box.leak()，或 mem.forget()。它占用的资源位于堆上。这种算内存泄漏，因为它是主动发起的。

### C-03 Borrowing（借用）

1. 借用规则是什么？用一句话说清楚"什么组合是允许的"。
  ~~借用的生命周期不能超过其借用值的生命周期。
  同一作用域中只能有一个活跃的可变借用，且可变借用与不可变借用不能共存。~~
  同一时间，同一个变量，要么只能有多个不可变借用；要么只能有唯一一个可变借用。
  允许的组合：多个只读借用与单个可变借用是互斥的。


2. 为什么要有这条规则？它防的具体是哪一类 bug？举一个 C 里的例子。
  这条规则解决了并发与单线程环境下的数据竞态和悬垂指针问题。

3. 同一条规则，在 Rust 里其实有**两个**执行时机。分别是哪两个？各自失败时会发生什么？
  同一条规则分别在编译期和运行期使用。
  编译期失败则会终止编译，无法生成最终二进制程序。
  运行期失败会导致程序失败，或者卡死。

4. 一个借用从哪一行开始算、到哪一行结束？是到作用域末尾吗？
  借用从被创建的那一行开始，到借用最后使用的那一行结束。不用到作用域结尾。

5. 有一种类型，方法签名写着 `&self`，却能改自己内部的值。这怎么可能？它靠什么保证安全？
  不会



### C-04 Lifetime（生命周期）

1. 生命周期标注会生成任何运行期代码吗？如果不会，它到底在约束谁？
2. 大部分函数不用写标注也能编译。省略规则在什么情况下**不够用**？
3. `fn longest(a: &str, b: &str) -> &str` 编译不过。编译器缺的是哪一条信息？

5. 有一种类型参数不占任何运行期空间，却能影响类型检查。它是什么？为什么需要它？

### 怎么让"销毁"变得可见（C-01 的关键手法）

销毁本身不打印任何东西。要观察它，得让被销毁的值**自己**留下痕迹 ——
给类型实现那个 trait，在里面往一个日志里写一条记录。
想清楚：日志和被记录的值，谁必须活得更久？这个约束怎么表达出来？

### compile_fail 样本的写法

编译失败的样本放在 `experiments/m1-ownership/compile_fail/`，首行声明期望错误码：

```rust
//! EXPECT: <你预测的错误码>
//! CLAIM: <这个样本违反了哪条规则>
```

然后在 `tests/` 里用 `rf_harness::compile_fail::expect_errors` 断言。
**先写** `EXPECT` **再编译** —— 反过来就只是抄写编译器输出，什么也没验证。

一个样本可能触发**多个**错误码。首行 MUST 把实际出现的全部列出，
`CLAIM` 里说明每个码各自对应哪条规则、哪个是另一个的派生结果。

### 编译器行为观察（C-01 / C-02）

```bash
tools/emit-mir.sh m1-ownership --example c01_ownership
```

在 MIR 里找：销毁的调用是**谁**插进去的、插在了哪个位置；
移动之后，源位置在 MIR 层面是什么状态。
MIR 文本一律是 NON-ASSERTION —— 抄进 OBSERVATIONS，不要写进断言。

## 4. 提示阶梯

逐级往下看，每次只看一级。

### C-01 Ownership

- **Hint 1（方向）**：不要想"Rust 怎么管理内存"，想"这段释放代码是**谁**写的、**什么时候**写的"。
C 里是你写的、运行时执行；Rust 里换了一个环节。换的是哪个环节？
- **Hint 2（位置）**：`tools/emit-mir.sh` 导出 MIR，搜 `drop`。你会看到源码里没写的东西。
数一数它出现了几次、在什么位置。
- **Hint 3（拆解）**：拆成两问 ——(a) 销毁**代码**从哪来？(b) 销毁**时刻**由什么决定？
这是两个独立的问题，很多人把它们混成一个。



### C-02 Move semantics

- **Hint 1（方向）**：先别看语法。问一个更基本的问题：如果两个变量指向同一块堆内存，
作用域结束时会发生什么？把这个后果想清楚，"移动"的必要性就自己出来了。
- **Hint 2（位置）**：`core/src/marker.rs` 里那个"赋值即复制"的 trait，
文档里明确说了它不能和另一个 trait 共存。找到那句话，想清楚为什么互斥。
- **Hint 3（拆解）**：用第 1 步做的销毁计数器，分别对两种类型做一次赋值，
数一数各自的销毁次数。数字会直接告诉你差别在哪。



### C-03 Borrowing

- **Hint 1（方向）**：借用规则常被记成一句口诀。别背口诀，问它防的是什么 ——
在 C 里写一个"边遍历边修改容器"的循环，想清楚会出什么事。
- **Hint 2（位置）**：同一条规则有两个执行时机。编译期的那个在 `compile_fail/` 里观察；
运行期的那个在 `core/src/cell.rs` 里 —— 找到记录借用状态的那个字段，看它怎么编码状态。
- **Hint 3（拆解）**：把"借用从哪行开始、到哪行结束"单独拿出来实验。
写一个可变借用，在它**最后一次使用之后**再取一个不可变借用，看编译器答不答应。
结果可能和你以为的作用域规则不一样。



### C-04 Lifetime

- **Hint 1（方向）**：把标注读成"给借用检查器的一句声明"，而不是"给值设定的存活时间"。
它不改变任何东西的寿命，只是**陈述**一个已经存在的约束。
- **Hint 2（位置）**：省略规则在 Rust Reference 里有明确的三条。找到它们，
然后拿 `fn longest(a: &str, b: &str) -> &str` 逐条套一遍，看卡在第几条。
- **Hint 3（拆解）**：先回答一个更小的问题 ——
编译器要给返回的引用推一个生命周期，它的**候选来源**有几个？
只有一个候选时能不能猜？有两个时呢？
