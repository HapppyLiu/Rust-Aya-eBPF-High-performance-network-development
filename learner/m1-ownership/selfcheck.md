## 五项检验

- [ ] **1. 自述概念**

  向"懂 C 但没学过 Rust 的同事"解释这四个概念。规则：每冒出一个 Rust 术语，
  要么当场用 C 世界的话解释，要么换掉它。

  特别注意"借用"和"生命周期"这两个词 —— 它们在日常语言里的含义会误导人。
  试着**不用这两个词**把 C-03 和 C-04 讲一遍。

- [ ] **2. 最小示例**

  为每个 Capability **默写**一段 ≤15 行代码。默写，不是复制。

  | C-ID | 要默写的东西 |
  |------|------------|
  | C-01 | 一个能让销毁变得可见的最小类型 |
  | C-02 | 同一行赋值、两种类型、两种后果的对照 |
  | C-03 | 一个会被借用检查器拒绝的最小片段 |
  | C-04 | 一个必须写显式标注才能编译的函数签名 |

- [ ] **3. 底层机制**

  说出编译器实际做了什么，**并指出你的依据来自哪个实验断言或哪处源码**。

  1. 释放代码是谁生成的、插在哪里？依据是哪一份 MIR 观察？
  2. 「移动」在机器层面做了什么、没做什么？依据是哪条断言？
  3. 借用检查在编译期和运行期各由什么执行？运行期那个用什么数据结构记状态？
  4. 生命周期标注在编译产物里留下了什么？

  说不出依据的那条，标记为"待补"—— 那正是第 5 节要出题的地方。

- [ ] **4. 常见误区**

  为每个 Capability 说出至少 1 条**你自己曾经的**误解，以及推翻它的证据。

  从别处抄来的"常见误区"没有诊断价值。如果你真的一条都没误解过，
  那就去看 `predictions.md` 里 `一致? = ✗` 的那几行 —— 那就是你的误解，白纸黑字。

- [ ] **5. 验证性问题**

  回答下列问题。答案不在本文件里。

  1. 一个值被移动之后，原来那个变量在 MIR 层面处于什么状态？
     它占的栈空间被回收了吗？作用域结束时编译器还会对它插入销毁调用吗？
  2. 为什么"赋值即复制"的那个 trait 和"定义销毁行为"的那个 trait **不能**同时实现？
     如果语言允许同时实现，会出什么具体的错？
  3. `RefCell` 并没有取消借用规则，它只是换了执行时机。那么它把什么**代价**引进来了？
     在什么场景下这个代价是不可接受的？
  4. 一个函数签名 `fn f<'a>(x: &'a str, y: &str) -> &'a str` ——
     `y` 没标注意味着什么？返回值和 `y` 有没有关系？
  5. `PhantomData<T>` 大小为 0，运行期不占空间。既然如此，
     它凭什么能让 `Tagged<A>` 和 `Tagged<B>` 变成两个**不能互相赋值**的类型？
  6. 如果编译器允许同一作用域存在两个 `&mut`，请构造一个具体的、会出错的程序。
     错在哪一步？这个错在 C 里对应哪个经典 bug？
